### 2026-09-03 · v3 작성

- `v3/` 폴더에 1층 전용 제어 프로그램을 새로 작성했다. `v1`, `v2`는 수정하지 않고 보존했다.
  - GUI: `v3/hydrogel_app/` (장비 설정은 `profile.py` 한 파일: 조그 `JF`/`JB`, 키보드 ←/→, 기본 포트 COM3/COM4, 로드셀 3 kg)
  - 펌웨어: `v3/firmware/compression_1F_mega_ramps/compression_1F_mega_ramps.ino`
  - 실행 파일: `v3/HydrogelStudio_1F.exe`
- 사용자 확인 사항 반영: 인디케이터는 단위 문자 없이 `xxx.x`(g)로 보내고 압축 시 음수이며, `JF`(전진)가 누르는 방향이고 800 steps/mm는 실측 확인됨.
- 버그 수정: v2 파서는 줄에 `kg`/`g` 문자가 있어야만 값을 읽어 실제 형식(`xxx.x`)을 읽지 못했다. 부호 반전을 적용해 압축력을 양수 N으로 표시한다.
- 버그 수정: Poroelasticity 모드가 모터 `DONE`과 함께 기록을 끝내던 동작을 고쳐, 목표 거리 도달 후에도 변위를 유지한 채 계속 기록한다.
- 동작 변경: `STOP`(비상 정지) 시 드라이버 전원을 끄지 않고 위치를 유지한다. 전원 차단은 별도 `MOFF` 명령(모터 전원 OFF 버튼)으로 분리했고 `MON`으로 재인가한다.
- 펌웨어 v3: 핀(60/61/56, 비상정지 D3), 통신 속도, steps/mm, 속도·가속도 상한은 v2와 동일하다. `MOFF`/`MON` 명령, `` 무시, 속도 상한 클램프, 즉시 정지(`haltNow`)를 추가했다.
- 이동 완료 판정을 Arduino `DONE` 신호 기준으로 바꾸고, 신호를 놓치면 예상 시간의 1.5배 + 2초 후 시간 기준으로 보조 판정한다.
- UI를 VS Code Dark+/Light+ 스타일(타이틀 바, 사이드바, 파란 상태 바)로 전면 재작성했다. 최대 하중 표시, 로드셀 용량 90% 경고, 설정 자동 저장(`%APPDATA%\HydrogelStudio\settings_1F.json`)을 추가했다.
- 검증: Python 3.10.11에서 문법 검사와 자동 테스트 9개(명령 생성, 파서, 설정 저장, 조그/시험/비상정지/전원 버튼 신호, 하드웨어 정지 신호, Poroelasticity 유지 기록) 통과. `--demo` 가상 장비로 밝은/어두운 테마 화면을 캡처해 레이아웃을 확인했다.
- 빌드: PyInstaller(`build.spec`)로 `v3/HydrogelStudio_1F.exe`를 생성하고 `--demo`로 실행해 창이 뜨고 응답하는 것을 확인했다.
- 미검증: 로컬에 Arduino CLI가 없어 펌웨어 컴파일을 하지 못했다. 실장비 포트 연결, 모터 이동, 로드셀 측정은 수행하지 않았다. v2 펌웨어와도 `start`/`JF`/`JB`/`STOP`/`DONE`은 호환되지만 `MOFF`/`MON`은 새 펌웨어를 올려야 동작한다.

### 2026-09-22 · v3.0.1 전체 검증 및 수정

- **거리 추정 오차 수정**: 거리 = 경과시간 × 속도 계산이 펌웨어 가속 구간(2.5 mm/s²)을 무시해 1 mm/s에서 약 0.2 mm를 과대평가했다. 새 `hydrogel_app/motion.py`가 펌웨어와 같은 사다리꼴 프로파일로 위치를 계산한다.
- **평균 기록 시 거리 짝 오류 수정**: 평균 힘을 버킷 끝 시각의 거리와 짝지어 저장하던 것을 시각·거리·힘 함께 평균으로 바꿨다.
- 시험 중 0점 변경 차단. 이동·조그 속도가 펌웨어 상한(5000 steps/s = 6.25 mm/s)을 넘으면 시작 거부.
- CSV를 매 줄 flush. 업데이트 교체 배치를 한글 경로 안전(CP949)·PID 정확 일치로 수정하고 실제 교체 동작 시험 통과. 시험 중에는 교체를 제안하지 않는다.
- 검증: 단위 테스트 17개 통과. exe 재빌드, v3.0.1 릴리스.

### 2026-11-02 · v3.1.0 작은 화면 대응 (창 맞춤, 패널 스크롤), 업데이트 교체 수정

- 문제: 창 높이가 860 px(최소 760 px)로 고정되어 화면이 작은 노트북에서는 창이 화면보다 컸다. 패널 아래쪽과 상태 표시줄이 화면 밖으로 나갔다. 창이 화면 밖으로 나가도 프로그램은 화면 밖 부분까지 보인다고 판단하므로, 스크롤만 넣으면 스크롤바가 나타나지 않거나 나타나도 화면 밖 부분까지 내려갈 수 없다. 그래서 창 맞춤과 스크롤을 함께 넣었다.
- 기능 추가: 새 모듈 `hydrogel_app/layout.py`. 실행할 때 작업 표시줄을 뺀 화면 영역에 맞춰 창 크기와 위치를 정한다. 큰 화면 1360×900, 최소 960×420. 화면 영역 값이 Tk 화면 크기보다 크면(배율 화면의 물리 좌표로 판단) 버리고 Tk 값을 쓴다.
- 기능 추가: 왼쪽 패널을 스크롤 영역과 고정 영역으로 나눴다. 연결·수동 제어·시험 설정은 스크롤되고, 내용이 넘칠 때만 스크롤바가 나타난다. 패널 내용 569 px, 고정 영역 184 px.
- 안전: 시험 시작·정지와 안전·모터 전원 버튼을 고정 영역에 두어 스크롤 위치와 관계없이 항상 보이게 했다. 이것은 요청에 없던 결정이며, 스크롤로 비상 정지가 가려지면 위험하기 때문이다.
- 입력: 휠 한 칸 60 px, 작은 휠 값은 모아서 처리. 포인터가 스크롤 영역 위에 있을 때만 움직이고, 고정 영역·그래프 위, 열린 콤보박스 목록, 조그 중에는 움직이지 않는다. 기록 속도 상자 위의 휠은 값을 바꾸지 않고 패널만 스크롤한다. 방향키는 바인딩하지 않았다(조그 전용).
- 포커스: Tab으로 가려진 입력칸에 들어가면 보이도록 스크롤한다. 휠로 입력칸이 가려지면 포커스를 뺀다. 숨은 값이 입력되거나 방향키 조그가 말없이 막히는 것을 막기 위해서다.
- 조그 플래그: `stop_test`, `disconnect_devices`, `STOP_BUTTON` 처리에서 `self.jogging`을 해제한다. 이 값이 남아 있으면 정지 후에도 휠 스크롤이 막혔다. 직렬 명령은 그대로이며, 정지 버튼이나 하드웨어 비상 정지 뒤 키를 떼거나 조그 버튼을 놓을 때 보내던 중복 `STOP` 한 번만 빠진다. 하드웨어 비상 정지 뒤에는 이때 상태 배지도 READY로 돌아가지 않고 STOPPED로 남는다.
- 메인 화면: 상태 배지를 먼저 배치해 잘리지 않게 하고, CSV 라벨은 남는 폭만 쓰며, 그래프 여백을 픽셀로 고정했다. 좁은 창에서 업데이트 버튼이 잘리지 않도록 타이틀 바 배치 순서를 바꾸고, 지표 사이 오른쪽 간격을 줄였다.
- 업데이트 수정(화면 요청과 별개이지만 이번 업데이트의 전달 경로라 함께 고쳤다): 교체한 새 exe가 이전 프로세스의 PyInstaller 환경 변수를 물려받아 지워진 `_MEI` 폴더에서 실행하려다 오류 창을 띄웠다. `PYINSTALLER_RESET_ENVIRONMENT=1`을 넘긴다. 교체 배치가 자식 프로세스만 기다려서, exe를 아직 잡고 있는 부트로더 부모 때문에 `move`가 실패하고 이전 버전이 남았다. 부모 PID를 기다린다. 다운로드가 끊겨 Content-Length보다 짧은 파일도 완료로 처리되어 교체될 수 있었다. 이제 오류로 처리한다. 버전 확인·다운로드 실패 안내는 `exc` 이름이 사라진 뒤 실행되어 대부분 NameError로 끝났고 버튼이 비활성으로 남았다. 이제 안내가 표시된다.
- 바꾸지 않은 것: 직렬 명령, 조그·키 동작, 시작·정지·비상 정지의 동작(조그 플래그 항목의 차이 제외), CSV 형식, 측정 계산, 펌웨어, v1·v2.
- 검증: 단위 테스트 57개 통과(새 테스트 40개). 수정을 하나씩 되돌리면 해당 테스트가 실패하는 것도 확인했다. 화면 영역을 1366×728, 1280×680, 1024×560으로 패치해 띄운 데모 화면을 캡처해 직접 확인했다. 내용 끝까지 스크롤되고 시험 시작·정지·비상 정지·모터 전원 OFF 버튼이 위치와 관계없이 보였다. 휠 메시지(WM_MOUSEWHEEL)를 자기 창에 보내 대상 위젯별로 처리기가 한 번씩 불리는 것을 확인했다(20개 항목). 스크롤 처리 코드는 4층과 글자까지 같으며, 1층에서는 실제 휠 입력을 넣지 않았다.
- 검증(exe): 최종 exe 안의 코드가 소스와 같은 것을 확인했다. `--demo`로 실행해 제목 v3.1.0, 창 위치, 창을 노트북 크기로 줄였을 때의 스크롤바와 고정 버튼을 확인했다.
- 검증(실제 exe 교체): 화면에 보이지 않는 별도 데스크톱과 한글 폴더에서, 실제 앱 코드를 넣은 시험용 exe로 `_download_done`, 교체 배치, 최종 exe 실행까지 돌렸다. 확인 창의 '예'만 코드로 대신했다. 최종 소스로 만든 시험용 exe는 층별 7회, 합계 14회 모두 오류 창 없이 v3.1.0 창이 열렸고 교체와 .bak 생성까지 정상이었다. v3.0.1 소스로 만든 시험용 exe는 층별 7회, 합계 14회 모두 오류 창이 뜨고 교체가 실패했다. 이때 내려받은 새 파일을 직접 실행하면 14회 모두 v3.1.0이 정상으로 열렸다.
- 미검증: 실제 소형 노트북, 실제 터치패드 제스처, 배율 125·150 % 화면에서의 실행은 시험하지 못했다. 배율 화면의 화면 영역 값은 Windows 코드 읽기와 방어 코드로만 대비했다. 화면의 버튼을 직접 눌러 진행한 업데이트와 다른 PC(백신, 느린 디스크)에서의 교체도 시험하지 못했다. 장비를 연결하지 않아 통신 연결, 모터 이동, 로드셀 측정은 수행하지 않았고, 직렬 출력은 가상 장치에 기록된 바이트로만 확인했다.
- 알려진 문제(이미 배포된 v3.0.x): 이전 버전의 교체 코드는 이제 고칠 수 없어, v3.0.x에서 자동 교체를 고르면 오류 창이 뜨고 교체되지 않을 수 있다. 다운로드 뒤 교체 질문에 '아니요'를 누르고 프로그램을 닫은 다음, 같은 폴더의 `HydrogelStudio_1F_v3.1.0.exe`를 실행한다. 데이터에는 영향이 없다.
- 기록 정정: 2026-09-22 v3.0.1 항목의 교체 동작 시험은 실제 exe가 아니라 일반 Python과 더미 파일로 한 것이어서 이 문제를 잡지 못했다.
- 알려진 문제(이번 변경 전부터 있었고 고치지 않음): `app.py`의 `_on_key_release`는 포커스가 입력칸에 있으면 키 뗌을 무시한다. 방향키를 누른 채 입력칸을 클릭하고 키를 떼면 `STOP`이 나가지 않아 정지 버튼이나 Esc를 누를 때까지 조그가 계속된다(가상 장치로 재현). 키를 누른 채 다른 프로그램으로 포커스가 옮겨 가도 같은 결과가 된다(코드 읽기). 펌웨어 조그에는 감시 타이머가 없어 실제 축은 계속 움직일 것으로 판단하며 실장비로 확인하지는 않았다. 조그 동작 변경이라 사용자 판단을 기다린다.
- 알려진 문제: `app.py`의 `_drop_hidden_focus`는 입력칸만 처리한다. 기록 속도 상자에 포커스가 있으면 휠로 가려져도 포커스가 남아 방향키 조그가 나가지 않는다(상자가 보일 때와 같다). 모터로 나간 바이트는 없었고 기록 속도 값은 바뀌지 않았다(가상 장치로 확인). 창을 줄여 입력칸이 가려지거나 Tab으로 포커스를 둔 버튼이 휠로 가려져도 포커스는 그대로다. 입력칸이면 글자가 가려진 칸에 들어가고 조그가 막히며, 버튼이면 스페이스 키가 가려진 버튼을 누른다(코드 읽기).
