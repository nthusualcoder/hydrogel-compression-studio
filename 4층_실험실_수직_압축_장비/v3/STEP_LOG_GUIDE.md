# STEP 로그 사용 안내 · 4층 v3.3.0

## 현장 PC 준비

1. Arduino IDE에서 `firmware/compression_4F_uno_r4/compression_4F_uno_r4.ino`를 연다.
2. 보드를 **Arduino UNO R4 Minima**로 선택하고 직접 업로드한다. 빌드는 Arduino Renesas UNO 코어 1.6.0, AccelStepper 1.64.0으로 확인했다. 이번 펌웨어는 기존 구동 방식에 진단 기록 기능을 추가한 것이다.
3. 현장 PC에서 `HydrogelStudio_4F.exe`를 실행한다. 검토용 `HydrogelStudio_4F_v3.3.0_review.exe`도 같은 기능이다. exe 사용에는 Python·VS Code·Codex 설치가 필요 없다. 펌웨어 업로드는 exe 업데이트와 별도다.

## 원할 때만 기록하기

1. 저장 폴더를 정하고 장비를 연결한다.
2. 연결 영역의 기본값 저장 버튼 옆 작은 **STEP 로그** 버튼을 누른다. 기본 상태는 OFF이며, 누르지 않으면 진단 CSV를 만들거나 Arduino 진단 데이터를 전송하지 않는다.
3. 펌웨어 응답을 받으면 버튼이 **로그 중지**로 바뀐다. 응답이 없으면 새 진단 펌웨어 업로드가 필요하다는 안내가 나온다. 기록 버튼 자체는 모터를 움직이지 않는다.
4. 원하는 속도로 조그 또는 압축 시험을 수행한다. 예: 0.00125, 0.0025, 0.00375, 0.005 mm/s. 가능하면 비교할 각 속도에서 충분한 틱 수를 기록한다. 기존 정지·비상 정지 버튼은 그대로 사용한다.
5. 움직임을 정지한 뒤 **로그 중지**를 눌러 저장 완료 안내를 확인한다. 기록을 끄는 버튼은 모터 정지 버튼과 별개다. 이동 중 눌러도 이동·시험 자체를 정지하지 않는다.
6. 저장 폴더의 **`STEP_4F_날짜_시각.csv`**를 이 컴퓨터로 복사해 채팅에 첨부하면 분석할 수 있다. 압축 시험 CSV와 별도 파일이며 여러 시험을 한 STEP 로그에 담을 수도 있다.

프로그램 종료·연결 해제 시에도 파일을 닫지만, 이때 마지막 Arduino 종료 응답까지 받지 못할 수 있다. 분석에 사용할 때는 로그 중지 버튼으로 먼저 정상 종료하는 것이 좋다.

## 기록 내용과 해석 범위

- `TX`: PC의 명령 전송 시작 시각과 쓰기 호출 소요 시간. `CMD`: Arduino가 수신한 명령과 Arduino 시각.
- `STEP`: STEP HIGH 출력 호출 직후의 Arduino 소프트웨어 시각, 누적 틱 수, 명령 위치(틱), 이전 연속 틱과의 실제 기록 간격, 라이브러리가 예약한 간격.
- `LOAD`: PC 수신 시각, 로드셀 g 원본과 0점 보정 후 N.
- `HEARTBEAT`/`OFF`: 전송 버퍼 누락 개수와 고속 상세 기록 생략 개수. 틱 순번의 불연속도 `seq_gap`에 표시된다.
- 상세 STEP는 **설정 속도 0.01 mm/s(8틱/초) 이하**에서 기록한다. 더 빠른 이동은 상세 STEP를 생략하고 누적 틱 수와 생략 수를 보고한다. 전송이 막혀도 모터가 로그를 기다리지 않도록 버퍼는 고정 크기이고, 한 줄을 보낼 여유가 있을 때 전송한다.
- PC 도착이 묶여도 `interval_us`는 Arduino의 발생 시각 차이로 계산한다. PC와 Arduino는 서로 다른 시계를 사용하므로 두 시각을 직접 빼서 편도 통신 지연이라고 해석하면 안 된다. PC `pc_elapsed_s`는 수신/전송 시각, `pc_time`은 행을 저장한 PC 시각이다.
- `micros()`의 약 71분 주기 넘침을 처리한다. 새 이동 명령 전후의 유휴 시간과 순번이 누락된 구간은 정상 단일 틱 간격 통계에서 제외한다.
- 기록은 디스크에 바로 쓰며 약 0.5초마다 flush한다. 비정상 종료 시 마지막 일부 행은 남지 않을 수 있다. 메모리에 전체 로그를 보관하지 않는다.

이 기록은 **펌웨어의 STEP 출력 동작을 관찰한 소프트웨어 로그**다. 핀 전압, 드라이버가 실제로 인식한 펄스, 모터 축의 실제 이동을 전기적·기계적으로 계측하는 것은 아니다. 기록 기능 자체의 실행 시간도 완전히 0은 아니다. 실제 전압 파형은 오실로스코프·로직 분석기, 실제 변위는 별도 센서로 확인해야 한다.

데모 모드의 파일은 첫 줄에 `"demo": true`라고 표시된다. 데모 시각은 가상 장비 갱신 주기 기반이며 실물 펄스의 타이밍 판단에 사용하지 않는다.

## 예상 등속 간격 (800틱/mm)

| 설정 속도 | 등속 구간 예상 간격 |
|---|---:|
| 0.00125 mm/s | 1,000,000 µs |
| 0.0025 mm/s | 500,000 µs |
| 0.00375 mm/s | 약 333,333 µs |
| 0.005 mm/s | 250,000 µs |

기존 AccelStepper의 출발·정지 구간은 별도로 확인한다. 전체 이동을 무조건 등속으로 판정하지 않는다.

개발 PC의 간단한 요약 명령: `python -m hydrogel_app.step_log <CSV 경로>`.

호스트 펌웨어 검사: MSVC 개발 도구와 `build/toolchain/user/libraries/AccelStepper`가 준비된 Windows에서 `python tests/run_firmware_host.py`. 실제 AccelStepper와 `.ino`를 가상 GPIO에 연결해 기록 시각·개수, 진단 ON/OFF의 구동 순서 일치, 버퍼 누락과 고속 생략을 검사한다. 실장비 계측을 대신하지 않는다.
